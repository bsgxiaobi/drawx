## 1. 一句话现状

Windows 免安装单文件图片标注工具 **已完成可日常使用**：一张画布上可以放**多张图片**（各是一个图片图层，可移动 / 缩放 / 旋转 / **非破坏裁剪**），有**图层面板**（显隐、锁定、排序、改名、复制、删除、不透明度），标注仍是矢量对象（矩形、椭圆、圆角矩形、直线、箭头、画笔、高亮、文字、马赛克、模糊），对象级撤销重做，`.drawx` 工程存取（v2，含 v1 自动迁移），导出与快速复制为图片。

**v0.2 的核心变化：背景位图这个概念没有了。** 原来的"背景"升级成最底下的一个图片图层 —— 因为"把现场多张照片拼成一张完整的图"要求每张照片都能被选中、移动、缩放、裁剪。详见 [设计方案.md 第 5 节](设计方案.md)。

## 4. 我怎么"自己用一遍"（GUI 实测流程）

零插件，纯 ctypes + Pillow：[`devtools/screen_agent.py`](../devtools/screen_agent.py)。

```powershell
$A = ".venv\Scripts\python.exe devtools\screen_agent.py"
& $A list                                                    # 列窗口（含 hwnd/尺寸/DPI）
& $A shot  --window 标注工坊 --out s1.png                     # 只截该窗口（会先钉到最上层）
& $A click --window 标注工坊 --x 300 --y 300                  # 坐标 = 截图里量到的位置（含标题栏）
& $A drag  --window 标注工坊 --x1 300 --y1 300 --x2 600 --y2 400
& $A key   --window 标注工坊 r                                # 单字母快捷键走 PostMessage
& $A key   --window 标注工坊 --real ctrl+s                    # 组合键必须加 --real
& $A hover --window 标注工坊 --x 600 --y 400                  # 报告鼠标光标形状
& $A realdrag --x1 1888 --y1 394 --x2 600 --y2 500            # 真实鼠标跨进程拖拽（测 OLE 拖放）
& $A winicon --window 标注工坊 --out icon.png                 # 抠出窗口真实图标
& $A crop --in s1.png --out zoom.png --box 0,0,300,200 --scale 2
& $A run devtools/scripts/gui_layers_edit.json                # 一串步骤一次跑完
```

**六条必须记住的经验**：

1. **组合键必须 `--real`**：伪造的 `WM_KEYDOWN` 不更新 `GetKeyState`，Qt 据此判断修饰键，`ctrl+s` 走 PostMessage 完全不认。
2. **测拖放必须 `realdrag`**：OLE 拖放只认真实输入队列。
3. **离屏平台没有字体、剪贴板是空实现** → 涉及字体/剪贴板/窗口图标的验证都上真实平台；离屏里**写**剪贴板会直接崩（不是挂住）。
4. **看截图要 `crop` 放大**，尤其图标、端点、面板行；并且 `crop` 不能越界（越界会补黑边）。
5. **坐标就是截图里的像素**（含标题栏），所以先 `shot` 再量；滑动条要量到**滑块中心**（差 10px 就会点到滑槽上，值不变）。
6. **`launch` 出来的子进程不能继承 stdout**，否则调用方的管道要等被测程序退出才 EOF（`run ... | ...` 会挂死）；`screen_agent` 已经把子进程 stdio 指向 DEVNULL。

**黄金验证套路**（`devtools/verify_gui_layers.py` 就是照这个写的）：GUI 只管点，**结果一律回读 `project.json` 核对**。像素看走眼的概率远高于文件读错。

## 6. 项目约定（改代码前先读）

1. **任何修改文档内容的操作都必须包在 `QUndoCommand` 里**，禁止直接改模型。撤销是**对象级快照**，不是像素回滚；图层的增删排序/显隐/锁定/不透明度也全部走命令。
2. **一个画布 = 一列图层**。`Document.layers` **顶层在前**（与图层面板行号一致，不要做反序换算）；绘制顺序是它的反序。
3. **对象的 z 是派生值**：由 `CanvasScene.reflow_z()` 按"图层顺序 + 图层内顺序"分配 1,2,3…。**不要手工设 z**；撤销/重做后场景会自动重排一次，所以快照里的旧 z 不会造成"对象偷偷换层"。
4. **图片图层 = 场景图元**（不是背景）。因此"选中→移动→缩放→旋转"直接复用标注的整套手柄机制。命中测试的优先级是：**标注 → 图片 → 框选**，见 `CanvasView.anno_at` / `image_at`。
5. **图片裁剪是非破坏的**：只改 `ImageItem.src_rect`，原图永远不动；裁剪编辑期会临时显示整幅原图（`begin_crop`/`end_crop`），切换工具时务必 `end_crop(None)` 复原。
6. **编辑态装饰只画在 `QGraphicsView.drawForeground()`**（选择框、控制点、裁剪框、参考线）。导出直接渲染 `QGraphicsScene`，所以装饰天然不会混进导出图。
7. **图层不透明度是乘数**：对象自己的 `style["opacity"]` 与 `_layer_opacity` 分开存，`apply_style()` 里相乘。对象的显隐同理（`_own_visible` 与图层显隐相乘）。
8. **零资源文件**：图标、应用图标全部用 `QPainter` 现画。改图标必须用 `devtools/icon_sheet.py`（各尺寸对照）+ `devtools/icon_variants.py`（多组参数并排）并排渲染验收，并用 `devtools/icon_metrics.py` 量一遍**墨迹重心**（`undo/redo` 曾经比旁边的图标高 1.8px，肉眼看不出、一量就现形），最后保证 `tests/icon_test.py` 全部通过（含"两态图标必须不同""箭头方向朝外""图标居中"）。
9. **序列化必须无损往返**：`to_dict()` / `apply_dict()` 一对；读工程时保留未知字段（顶层 + 图层级），配合版本号 + 迁移链；**改格式就写一条迁移**（v1→v2 见 `serialize._migrate_1_to_2`）。
10. **所有坐标都要乘 `size`**（图标绘制）；漏乘会缩成 1 像素的小点。
11. **关键功能要留保底快捷键**（见环境事实里的输入法问题）。
12. **测试分层**：逻辑测试走离屏平台；剪贴板/字体/窗口图标/真实点击必须真实平台。**GUI 改动要回读工程文件核对**，别只看截图。
13. 中文界面；`_set_edit_guard()` 在文字编辑期间禁用会抢按键的 QAction；整份替换文档时用 `_loading_document` 挡住"未保存"标记。
14. **界面文案必须全中文，包括 Qt 自己造的按钮**。`app.install_translations()` 装 `qtbase_zh_CN.qm`（提示框按钮、文字编辑右键菜单等），另外**我们自己弹的框一律走 `ui/dialogs.py` 的封装再显式写一遍中文** —— 不能只依赖 `.qm`：打包时万一没带上，用户看到的就是 `Save / Discard / Cancel`（就是这么被用户抓到的）。`dialogs.py` 里 `Discard` 用的是国内习惯的「不保存」而不是 Qt 的「丢弃」。
15. **上面这些纪律尽量挂测试**：图标尺寸与重心、QSS 里不许出现箭头子控件、`Ctrl+Shift` 必须有保底、文字编辑期间禁用抢键动作、工具默认样式不覆盖用户值 —— 这 5 条现在都有断言，改到相关代码时跑 `icon_test` / `ui_test` / `interaction_test` 就会拦住。

> 改代码前先扫一眼 [设计方案.md 第 11 节「已知坑、注意事项」](设计方案.md)：那里只列**现在还有效**的规则与取舍（注意事项 / 已知坑两类），其中 5 条已经挂了自动化断言。已经修好的历史问题（含现象/根因/修复）存档在 [踩坑记录.md](踩坑记录.md)，追溯"代码为什么长这样"时再查。

## 7. 已完成（摘要）

**v0.1**：导入图片（对话框/拖拽/`Ctrl+V` 粘贴/EXIF 正位）· 非破坏裁剪 · 10 类标注对象 · 选择/多选/框选 · 移动/缩放/旋转 · 属性面板 · 复制粘贴对象 · 对象级撤销重做 · `.drawx` 存取 · 导出 PNG/JPG/WebP/BMP（1x–4x 矢量重绘）· 快速复制为图片 · 深色主题与矢量图标 · 单文件 exe 打包与自检。

**v0.2（本次）**：

- **多图片图层**：`Ctrl+I` 多选导入 / 拖入多张 / 粘贴截图，各成一个图片图层；自动按行铺开、自动扩画布
- **每张图片都能移动、8 控制点缩放、旋转、非破坏裁剪**（`C` 选中图片后框选，会临时显示整幅原图）
- **图层面板**：缩略图、眼睛（显隐）、锁（锁定＝画布上选不中，面板操作照常）、拖动排序、▲▼/置顶/置底、双击改名、复制/删除、不透明度滑块（实时预览 + 单条撤销）
- **画布菜单**：画布大小…（**一个对话框同时设宽高 + 比例预设 1:1 / 4:3 / 3:4 / 16:9 / 9:16 + 交换宽高**）、画布适应内容（`F9`）、**自动排列图片图层**（网格统一缩放，多图拼一张）、三种背景色
- **图层菜单**：新建图片/标注图层、复制、删除、上移/下移/置顶/置底、显隐、锁定、重命名、重置图片裁剪；选中图片时属性面板只显示图片相关项
- **命中测试与框选规则重做**：标注永远优先于图片（否则空心矩形压在照片上会选不中）；图片上拖动＝移动图片，`Shift+拖动`＝框选标注
- **`.drawx` v2**：资源按 `assetId` 分开存（`assets/img-xxx.png`），**v1 工程自动迁移**（背景位图升级成图片图层），图层属性/未知字段往返无损
- **马赛克/模糊改为采样下方所有图片图层的合成结果**（带几何指纹缓存），多图拼合后依然正确
- 修掉两个真机才能发现的 bug：新建文档后立刻被问"要保存吗"（`undoStack.clear()` 触发 `indexChanged`）、`app.quit()` 触发未保存确认框导致脚本挂死
- **界面中文化补全**：装了 Qt 的 `qtbase_zh_CN` 翻译，并让所有自己弹的提示框/输入框显式用中文按钮（保存 / 不保存 / 取消、确定 / 取消）—— 之前"尚未保存"框上是 `Save / Discard / Cancel`

用户四轮反馈的问题均已修复并记录：箭头端点露线帽、空白画布渲染异常、拖入文件无效、下拉与撤销图标粗糙、exe 有图标但窗口没有、撤销箭头角度过大。

**已知取舍**：

- **在图片上拖动＝移动图片**，框选标注要 `Shift+拖动`（或点图层行整层选中）。这是为了让"拖进来就能拖走照片"成立 —— 多图拼合场景里移动照片是最高频动作。
- 多选支持移动/删除/改样式/改层级，**不支持整体缩放**。
- 马赛克/模糊只采样**图片图层**，不采样它下面的标注。
- 撤销栈上限 100 条（`const.UNDO_LIMIT`）。

## 9. 给下一位的一句话建议

先跑第 3 节那七条离屏测试确认基线是绿的，再跑 `devtools\verify_gui_layers.py`（真机端到端，19 项）——**这个项目里最值钱的 bug 全是在"真的用一遍"时冒出来的**：空白画布缩成一个点、拖放被 viewport 吃掉、`Ctrl+Shift` 被输入法拦掉、空心矩形压在照片上选不中、`app.quit()` 被未保存确认框挂死，单元测试一个都发现不了。GUI 改动**一定要回读 `.drawx` 里的 `project.json` 核对**，不要只凭截图判断。改动较大时记得重新打包并跑 `--selftest`。
