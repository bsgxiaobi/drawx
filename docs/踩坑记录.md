## 1. v0.1：真机实测才发现的问题

纯单元测试发现不了，都是把程序真跑起来、用鼠标点出来的：

| 现象 | 根因 | 修复 |
|---|---|---|
| 导入图片后标题仍是"无标题"，看不出在编辑哪张图 | 导入函数只设了 `doc.modified`，没记住来源文件 | `Document.source_path` + `display_name`，标题与默认文件名都用它 |
| 撤销后属性面板还显示旧值（矩形已变细线，面板仍写"线宽 40"） | 撤销不改选中集合，面板收不到 `selection_changed` | `undo_stack.indexChanged` → `property_panel.sync()` |
| 裁剪工具按钮是空白的 | 图标坐标漏乘 `s`，缩成 1 像素 | 乘 `s`；`icon_test` 现在会扫描全部图标查尺寸与重心 |
| 启动后按 R/A/T 没反应，必须先点一下画布 | 焦点在菜单栏/工具栏，单字母快捷键挂在视图上 | `MainWindow.showEvent()` 里 `view.setFocus()` |
| 裁剪框在非裁剪模式下几乎看不见（导出范围看不出来） | 单色 1px 细线，在白底或深底必有一种看不见 | 改为"黑色实线 + 白色虚线"叠画 |
| 拖控制点时鼠标不变形，用户不知道那里能拖 | 没有悬停光标反馈 | 按控制点方向切换 8 向缩放光标，旋转柄用十字 |
| **双击 exe 的默认空白画布缩成一个几十像素的小点，根本看不见画布** | `fit_to_window()` 在窗口还没布局完时被调用（视口只有几十像素），算出的缩放是 0.016 这种垃圾值；`_zoom` 又被 clamp 到 `MIN_ZOOM`，缓存值和真实变换从此不一致 | `fit_to_window()` 遇到退化视口直接跳过并记 `_fit_pending`，等 `resizeEvent` 补上；`_zoom` 一律以 `transform().m11()` 为准 |
| 箭头尖端露出线条的圆头端帽，尖端发糊有个小凸起（用户反馈） | 线杆一路画到端点，`RoundCap` 会超出端点半个线宽，正好戳在箭头尖上 | 线杆止于箭头底部（`inset = 箭头长度 × 0.86`），尖端保持锐角 |
| 图片 / `.drawx` 拖进窗口没反应（用户反馈） | `QGraphicsView` 的 viewport 默认 `acceptDrops=True`，事件被它接走转给场景，主窗口收不到 | 文件拖放实现在视图这一层，并显式 `event.ignore()` 拒绝不支持的类型 |
| 下拉框/微调框的箭头又小又黑，撤销/重做是纯黑三角（用户反馈） | 用的是系统标准图标 | `DarkStyle(QProxyStyle)` 自己画浅色雪佛龙；QSS 里不碰这些子控件 |
| `Ctrl+Shift+S`（另存为）按了没反应（用户反馈） | **中文输入法拦截了 `Ctrl+Shift` 组合键** | 另存为加 `F12`、复制图片用 `Ctrl+Alt+C`；`ui_test` 现在会断言"每个 Ctrl+Shift 都有保底" |
| exe 有文件图标，但标题栏和任务栏没有（用户反馈） | PyInstaller `--icon` 只设置 exe 的资源图标 | `QApplication.setWindowIcon()`；图标绘制收在 `ui/appicon.py` 一处 |
| 给 `QComboBox::drop-down` 写了 QSS 之后箭头彻底消失 | QSS 一旦声明子控件就由样式表自己绘制，没给 `image` 就什么都不画 | QSS 里不碰这些子控件；`ui_test` 现在会断言样式表里没有 `::drop-down` 等选择器 |
| 撤销/重做箭头又小又往弧线内侧勾（用户反馈） | 收尾角贴着椭圆左端点，那里切线几乎垂直向下、曲率半径只有平均值的 2/3 | 收尾角 175°→138°、外偏 19°、箭头长度 0.16→0.205；`icon_test` 用**该处**曲率半径校验 |
| "尚未保存"框上的按钮是 `Save / Discard / Cancel`（用户反馈） | 界面文案全中文，但 Qt 标准按钮的文案来自 `qtbase_zh_CN.qm`，程序没装翻译 | `app.install_translations()` 装翻译；自己弹的框额外显式写一遍中文（保存/不保存/取消） |
| 设置画布大小要连弹两次输入框（用户反馈） | 用两个 `QInputDialog` 分别问宽和高 | 新 `CanvasSizeDialog`：一个框设宽高 + 比例预设 + 交换宽高 |

## 2. v0.2 图层化之后

| 现象 | 根因 | 修复 |
|---|---|---|
| 空心的矩形/椭圆压在照片上时，点框内选不中矩形 | 命中测试"先精确命中、再容差兜底"，而照片是实心的，精确命中永远先命中照片 | 合并成一次判断：精确命中与容差命中各取候选，**比较 z 取更高者**；并让 `anno_at` 只找标注、图片走 `image_at` |
| 新建文档后什么都没做就弹"要保存吗" | `QUndoStack.clear()` 会发 `indexChanged`，而该信号里要把文档标脏 | 整份替换文档期间置 `_loading_document`，此时不置脏 |
| 脚本里 `app.quit()` 之后进程不退出（挂死） | Qt 6 的 `quit()` 会关闭顶层窗口 → 触发"未保存"确认框 → 无人值守时没人能点 | 脚本退出前先 `doc.modified = False`（`tests/render_shot.py`） |
| 撤销一次移动，对象"偷偷跑到别的图层上面" | 快照里有 `z`，撤销时 `apply_dict()` 把它写回，而期间图层顺序可能已经变过 | z 全部派生自图层顺序（`reflow_z()`），并在 `undo_stack.indexChanged` 里重排一次 |
| 锁定图层后连不透明度都改不了（自动化验证直接失败） | 把"锁定"实现成禁用一切编辑 | 锁定只挡画布交互（选不中、拖不动），面板里的显式操作照常 |
| 画的标注进了照片图层：一隐藏照片标注跟着消失 | 导入图片后"当前图层"留在图片图层上 | `default_annotation_layer()` **永不返回图片图层**；导入图片后当前图层切回标注层 |
| 图片裁剪中途按 Esc / 切工具，画面里留一张"变大了的图" | 裁剪编辑态会临时显示整幅原图，退出时忘了复原 | `CropTool.reset()` 与 `key_press(Esc)` 都调 `end_crop(None)` |
| 图层顺序调整后，右下角拖不动/选不中（图层化早期的行为回归） | 见第 1 行同一条命中测试问题 | 同上 |
| `screen_agent run x.json \| ...` 一直不返回 | 启动的被测程序继承了 stdout，调用方的管道要等它退出才 EOF | 子进程 stdio 指向 DEVNULL |
| `screen_agent list` 抛 `UnicodeEncodeError: 'gbk'` | 中文控制台代码页是 GBK，窗口标题里有个 ❓ 之类的字符就崩 | 工具启动时把 stdout/stderr `reconfigure(encoding="utf-8", errors="replace")` |
| 自动化脚本里"图层不透明度没生效" | 量错了坐标：滑条的 x 差 5px（点到滑槽上）、y 差 13px（点在滑条外） | 先 `shot` 再量、量滑块中心；**结论一律回读 `project.json`**，不靠像素判断 |

## 3. 从这些坑里沉淀出的规则

已经整理进 [设计方案.md 第 11 节「已知坑、注意事项」](设计方案.md#11-已知坑注意事项)，
并且其中 5 条已经从"文档纪律"升级成自动化断言：

| 规则 | 现在的兜底 |
|---|---|
| 图标坐标必须乘 `size`，图标必须居中 | `icon_test` 扫描 `tool_icon` 源码里的全部 28 个图标，逐个查墨迹尺寸、重心、以及 16/32/48px 下不空白 |
| 样式表里不能出现 `::drop-down / ::up-button / ::down-button` | `ui_test` 断言（会先剥掉注释，因为样式表里的警告注释本身含这些词） |
| 每个 `Ctrl+Shift` 快捷键都要有非 Ctrl+Shift 的保底 | `ui_test` 遍历全部 QAction 断言 |
| 文字编辑期间要禁用会抢按键的动作 | `interaction_test` 断言编辑期间 undo/redo/全选/删除/复制全部禁用、结束后恢复 |
| 工具自带的默认样式不能覆盖用户显式调过的值 | `interaction_test` 断言"调过不透明度后高亮不再强制半透明、没调过仍然半透明" |
