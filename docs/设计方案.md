# 轻量图片标注工具 — 功能设计与技术选型

> 版本：v0.1（设计稿）
> 目标：Windows 单机桌面工具，**位图背景 + 可任意再编辑的矢量标注对象 + 工程文件**，可导出 PNG/JPG。
> 定位一句话：**微信截图的编辑手感 + Photoshop 的"工程文件可再编辑"，但不要 Photoshop 的重量。**

## 0. 结论摘要（TL;DR）

> **v0.2 补充（先读这一条）**：第 1–8 节是最初的设计稿，其中"背景位图"与"图层面板未实现"两处**已被实现推翻** ——

> 实现与设计稿的全部差异见文末"附：实现状态（v0.2）"的第 9–12 节。

| 决策项 | 结论 |
|---|---|
| 技术栈 | **Python 3.11/3.12 + PySide6 (Qt Widgets) + QGraphicsScene**，PyInstaller 打包单文件 exe |
| 备选栈 | Web(Fabric.js v6) + Tauri 2（体积小、跨平台，但需要 Node+Rust 双工具链） |

| 单文件 exe 体积 | 约 **55–80 MB**（onefile + 排除无用 Qt 模块），冷启动 2–4 s；实测 **41.1 MB** |
| 首次可运行版本（P0） | 约 6–9 人日（有 AI 辅助实现的情况下） |

## 1. 需求边界：为什么现有工具都不合适

用户诉求拆成三条硬性条件，市面上满足全部三条的工具基本不存在：

1. **标注对象可任意再编辑**（不是画上去就变像素）；
2. **能存工程文件，下次打开继续改**；
3. **轻**（不要 Photoshop）。

现有工具逐条核对：

| 工具 | 对象可再编辑 | 工程文件 | 体积/门槛 | 可借鉴之处 |
|---|---|---|---|---|
| Windows 画图 | ✗ 形状落笔即栅格化，只能靠"向后撤销" | ✗ | 系统自带 | **反面基准**（就是用户的痛点来源） |
| 微信截图编辑 | ✗ 导出即扁平 | ✗ | 免费 | **工具集与手感的基准**（箭头、序号、马赛克、文字） |
| Snipaste | ✗ 官方 issue 里用户长期在求"保存成可二次编辑的 .snip" | ✗ | 免费 | 贴图/快捷键体验 |
| PixPin | ✗ | 仅有截图历史回溯，非矢量工程 | 免费 | 历史回溯的交互 |
| ShareX | ✗ | ✗ | 免费开源 | 步骤序号、自动编号 |
| Paint.NET | 图层 ✓ / 形状 ✗（社区论坛同样在问"保存后如何再改"） | `.pdn` ✓ | ~10 MB | 图层交互、轻量定位 |
| Excalidraw / tldraw | ✓ | `.excalidraw` / `.tldraw`（JSON）✓ | 网页 / Electron | **文件格式与对象模型的范本** |
| miniPaint | 图层 ✓ / 形状 ✗（提交即栅格化） | JSON 工程 ✓ | 网页 | 工程文件 + 导出流程 |
| Krita / GIMP / Photoshop | ✓ | ✓ | 数百 MB ~ 2 GB | **明确的反面：太重** |
| **本项目** | ✓ | `.drawx` ✓ | 单个 exe ≈ 60 MB | ← 这块空白 |

**关键洞察**：能存工程文件的（PS / Excalidraw / miniPaint）要么太重、要么是绘图工具而非"标注图片"的流程；标注手感好的（微信 / Snipaste / ShareX）都不存工程。所以本项目的差异化就一句话：

> **一张画布上可以放多张图片（图片图层），标注全是矢量对象，全部可选中、可拖动、可改样式、可改层级、可撤销——并且整个文档可以存成一个文件。**

顺带两个免费的差异化优势：

- **非破坏性裁剪**（两层）：导出范围（`crop`）与每张图片的保留区（`src_rect`）都只是文档属性，随时改回来；微信/PS 裁剪后原图信息就丢了。
- **多图拼合**：把现场十几张照片拖进来 → 自动排列成网格 → 逐张调整/裁剪 → 圈画标注 → 导出一张完整的图。这一步在 PS 里要做十几分钟，在这里是本能操作。

### 2.4 视图与画布

- 缩放：`Ctrl+滚轮`（以鼠标为中心）、`Ctrl+0` 适应窗口、`Ctrl+1` 100%。
- 平移：按住空格拖动 / 中键拖动 / 滚动条。
- 画布边界外显示深灰底，导出时按 `crop` 区域裁切。
- **画布尺寸可变**：图片放不下时自动长大；「画布 → 画布大小…」在**一个对话框**里同时设宽高，可选 1:1 / 4:3 / 3:4 / 16:9 / 9:16 预设比例（选了比例后改任一边自动换算，另有「交换宽高」按钮）；「画布 → 画布适应内容」（`F9`）把所有内容收进画布并去掉空白边。
- **高 DPI**：启用 per-monitor DPI 感知（`PassThrough` 舍入策略），界面清晰且与导出分辨率无关。

### 2.5 文件与导出

**入口**
- `新建` → 空白画布（默认 1280×800）
- `添加图片图层`（`Ctrl+I`，**可多选**）/ 拖拽图片文件进窗口（**多张一起收下**）/ `Ctrl+V` 粘贴系统剪贴板截图 ← **最高频入口**，每张图各成一个图片图层
- 导入手机照片时按 EXIF 方向自动旋转（`QImageReader`/Pillow 取 EXIF）

**保存**
- `Ctrl+S` 保存 `.drawx` 工程（**含每个图片图层的原始位图**，换机器/挪文件仍可打开）
- 自动保存：每 60 s 或每 20 次操作写 `%LOCALAPPDATA%\DrawX\autosave\`，崩溃后启动时提示恢复（未实现）
- 最近文件列表（最多 10 个，缩略图已随工程保存）（未实现）

**导出（`Ctrl+E`）**
- 格式：PNG / JPG / WebP / BMP
- 倍率：1x / 2x / 3x / 4x（**矢量重绘，2x 导出文字与线条依然锐利**，不是插值放大）
- JPG 自动铺白底（JPG 无透明通道）并可设质量 1–100
- **快速复制为图片**：把"拼合后的整幅画布"以 PNG 放进剪贴板（同时给位图与 `image/png` 两种格式）

**文件关联**
- 提供绿色版：首次运行提示"是否关联 `.drawx`（仅写 HKCU，无需管理员）"，之后双击工程文件直接打开（未实现）。

### 2.6 撤销 / 重做

- 使用 Qt 自带 `QUndoStack` + `QUndoCommand`（免费获得：撤销/重做动作文本、栈深度限制、`mergeWith` 合并）。
- **对象级撤销**，默认 100 步，不是像素级：撤销一次"移动箭头"是恢复它的坐标，而不是回退整张位图 → 内存占用极小、任何历史状态都能追溯。
- 拖动/滑块类连续操作通过 `mergeWith` 合并为**一步**撤销（例如"调线宽 1→8"只算一步）。
- 所有修改文档的动作**必须**走命令栈（架构纪律，见 3.4）。

## 3. 核心架构设计

### 3.1 文档模型（唯一真相源）

```
Document
├── meta:        {format, version, app, createdAt, updatedAt}
├── canvas:      {width, height, background}       # 画布逻辑尺寸与底色
├── crop:        Rect                              # 非破坏裁剪窗口（导出范围）
├── assets:      {id → Asset{path,mime,sha256}}    # 每个图片图层一份原始位图
├── layers:      [Layer{id,name,type,visible,locked,opacity,objects:[Object]}]
├── view:        {zoom, panX, panY}                # 打开时恢复视图
└── settings:    {snapEnabled, gridSize, fontDefault…}
```

`Object` 是所有标注的基类数据（纯数据，不含 Qt 对象）：

```
Object
├── id, type, layerId, z, locked, visible
├── transform: {x, y, w, h, rotation, flipH, flipV}
├── style:     {stroke, strokeWidth, strokeStyle, fill, fillOpacity,
│               opacity, lineCap, lineJoin, dash, arrowHead, font…}
├── geometry:  类型专有（arrow: from/to；freehand: points[]；text: content/align；
│              mosaic: rect + blockSize；image: assetId + srcRect + natural）
└── createdAt, updatedAt
```

**设计要点**：模型里**不存像素**（图片图层除外 —— 它的原始位图必须内嵌，否则工程文件挪机器就丢图）。模型是可序列化、可 diff、可版本迁移的纯数据；Qt 的 `QGraphicsItem` 只是它的"视图 + 交互层"。

> **实现后修正（v0.2）**：运行期并没有一份独立的"纯数据 Object 树"。真实做法是**图元持有实时状态 + 快照式序列化**：`QGraphicsItem` 子类自己就是活模型，`to_dict()/apply_dict()` 一对方法负责快照与还原，保存时才生成上面这份 JSON。图层是唯一"真·模型对象"（`model/layers.py`），因为它不画任何东西、只描述归属与状态。
>
> 另一处重要修正：**`layers` 顶层在前**（列表第 0 项就是图层面板最上面那行），绘制顺序是它的反序；对象的 `z` 是**派生值**，由 `CanvasScene.reflow_z()` 按"图层顺序 + 图层内顺序"统一分配。这样"图层顺序"永远只有一份真相，不会出现 z 与列表打架。

### 3.2 工程文件格式 `.drawx`

**容器 = zip**（单文件、体积小、标准库即可读写，无需额外依赖）：

```
photo.drawx (zip)
├── project.json             # 上面那份文档模型，UTF-8，缩进 2 空格，便于人工排查
├── assets/
│   └── img-xxxxxxxx.png     # **每个图片图层**一份原始位图（按 assetId 命名，无损）
├── thumbnail.png            # 256px 缩略图，用于"最近文件"与资源管理器预览
└── README.txt               # 可选：说明本文件是 DrawX 工程
```

> v1 只有一张 `assets/background.png`（唯一的背景位图）。v2 起图片图层可以有任意多个，资源按 `assetId` 分开存；v1 文件打开时由 `serialize._migrate_1_to_2` 把背景位图升级成最底下的图片图层，显示效果不变。

```json
          "geometry": { "assetId": "img-4d13e7", "sourceName": "site_1.png",
                        "naturalW": 640, "naturalH": 480,
                        "srcX": 143, "srcY": 170, "srcW": 404, "srcH": 235 } }
      ] }
  ],
  "view": { "zoom": 0.54, "panX": 0, "panY": 0 }
}
```

图片对象的三个关键字段：`assetId`（去 `assets` 里取原图）、`naturalW/H`（**原图**尺寸，永远不变，用于"重置裁剪/原始大小"）、`srcX/Y/W/H`（非破坏保留区）。`w/h` 是它在画布上的显示尺寸，与保留区之比就是"一个源像素占多少画布单位"。

**兼容性策略**（省未来的事）：
- 读到未知字段**原样保留**（顶层与图层级都保留），保存时写回（未来版本新增字段不会丢）。
- `version` 递增 + `_migrate` 里写迁移函数链（v1→v2→…）。**改格式就必须加一条迁移**。
- 读取失败时给出明确错误（zip 损坏 / 缺 project.json / 版本过新）；某张图片的位图缺失时不算失败，画成占位框并在状态栏提示有 N 张缺失。

### 3.3 渲染与导出管线

**三层解耦**：

```
Document（数据）
   ↓ 同步
QGraphicsScene（渲染 + 命中测试 + 交互）
   ↓ 渲染
QGraphicsView（视口、缩放、选择框与控制点）
   ↓ 离屏渲染
QImage → PNG / JPG / WebP
```

三个关键技巧：

1. **选择框、控制点、参考线画在 `QGraphicsView.drawForeground()` 里，不画在 item 上。**
   - 手柄尺寸与缩放无关（在 viewport 坐标系画，或 `painter.resetTransform()` 后按 `mapFromScene` 定位）；
   - 导出时直接 `scene.render()` 到 QImage，**控制点天然不会出现在导出图里**，不需要"取消选中→渲染→恢复选中"这种脆弱做法。

2. **导出走"文档重新矢量渲染"，不抓屏。**
   - 导出倍率 S：`painter.scale(S, S)` 后把 `crop` 区域渲染到 `w*S × h*S` 的 QImage；
   - 文字、线条、箭头都以矢量重绘，2x/4x 导出依然锐利；画笔曲线用 `QPainterPath` 二次贝塞尔平滑，避免折线锯齿；
   - JPG 导出前先铺白底；PNG 保留透明。

3. **马赛克/模糊是非破坏的"区域对象"。**
   - 对象只记录区域 + 参数（`blockSize` / `radius`），渲染时**采样它下面的图层**，做像素化 / 高斯模糊，再画上去；
   - 因此它可以随时移动、缩放、调强度、删除——这是和"画上去就变像素"的本质区别；
   - 实现：像素化用纯 Qt（`QImage::scaled(w/bs, h/bs, FastTransformation)` 再放大回来，两行代码）；高斯模糊用 Pillow（`ImageFilter.GaussianBlur`，顺带 Pillow 还能处理 EXIF 与高质量缩放）；
   - **v0.2 修正**：不能再假设"背景是一张位图"。`render/backdrop.py` 会把**所有 z 比它低的图片图层**按各自的变换/不透明度合成成一张位图再采样，并且用"下方图片图层的几何指纹"做缓存键，所以拖动照片、改缩放、改顺序、改图层不透明度都会自动失效缓存，交互时不会每帧重算。
   - 采样粒度约定：**1 场景单位 = 1 像素**（与导出一致），代价是放大倍数很高的图片上马赛克边缘略软 —— 换来"块大小在任何缩放下语义稳定"。
   - 语义决策：马赛克只采样**背景层**，不采样其他标注对象 → 移动马赛克区域时不会把箭头也糊掉，符合直觉。

### 3.4 命令栈（架构纪律）

```python
class MoveObjectCommand(QUndoCommand):
    def __init__(self, doc, obj_id, old_pos, new_pos):
        super().__init__("移动对象")
        ...
    def undo(self): doc.set_transform(self.obj_id, self.old_pos)
    def redo(self): doc.set_transform(self.obj_id, self.new_pos)
```

铁律：**任何修改 `Document` 的代码路径都必须包在 `QUndoCommand` 里**，禁止直接改模型。收益：
- 撤销/重做全自动，且是对象级（内存友好）；
- 拖动过程中只更新"临时预览变换"，松手时提交一条命令（配合 `mergeWith` 合并滑块调整）；
- 保存时"脏标记"逻辑简单可靠。

### 4.2 推荐：方案 A（Python + PySide6）

理由，按权重排：

1. **`QGraphicsScene` 正好解决本项目最难的部分**——可选中/可拖动/可缩放旋转的矢量对象、z 序、命中测试、碰撞检测、视口裁剪。用 Tkinter 这些要写几千行；用 Qt 是"继承一个类 + 填 `paint()`/`boundingRect()`"。
2. **位图与图像处理是 Python 的舒适区**：马赛克/模糊/EXIF/高质量缩放/多格式导出，Pillow 几行搞定；将来想加"智能擦除/AI 去水印"也能直接接。
3. **打包链路最短**：`PyInstaller` 一条命令产单文件 exe，没有 Node/cargo 工具链、没有 IPC 序列化、没有前端构建产物管理。对"单人 + AI 辅助"的项目，这个省下的时间远大于 60 MB 体积的代价。
4. **原生体验最完整**：文件对话框、剪贴板图片、拖拽文件、最近文件、文件关联、单实例、托盘，Qt 都有现成 API，浏览器沙箱里这些全是坑。
5. **授权干净**：PySide6 是 LGPL，闭源分发没问题（PyQt6 是 GPL，**不要用**）。

**方案 A 的代价（如实说明）**：
- 单文件 exe 55–80 MB、冷启动 2–4 s（onefile 需要解压到临时目录）；
- onefile 容易触发个别杀软误报；
- 控制点交互（旋转后缩放、多选）需要自己实现好，是整个项目最花时间的部分（约 1.5–2 人日）。

**打包策略（三选一）**：

| 策略 | 产物 | 体积 | 冷启动 | 建议 |
|---|---|---|---|---|
| PyInstaller `--onefile` + UPX + 排除无用模块 | 单个 `DrawX.exe` | 55–80 MB | 2–4 s | **默认**，"双击就能跑"最省事 |
| PyInstaller `--onedir` + 7-Zip SFX 自解压 | 单个 `DrawX-Setup.exe`（首次解压到 `%LOCALAPPDATA%`，建快捷方式） | 下载 ~40 MB，安装后 ~120 MB | <1 s | 想要快启动又要单文件下载时用 |
| Nuitka `--onefile` | 单个 exe | 相近或略小 | 略快 | 追求极致时可替换，代价是编译时间长 |

无论哪种都配合：`--exclude-module` 剔掉 QtWebEngine/Qt3D/QtMultimedia/QtQuick 等（能省 30–50 MB）、图标与版本信息、`--noupx` 视杀软报毒情况切换、可选代码签名消除 SmartScreen 警告。

### 4.3 备选：方案 C（Fabric.js v6 + Tauri 2）

如果你更在意**体积（10 MB 级）**或**未来要有 Web 版**，这是更好的选择：
- Fabric.js v6 的对象模型与 JSON 序列化几乎就是本设计的 Web 版实现，开发量比 Qt 还小；
- Tauri 2 产物 ~10 MB、启动快、内存低；
- 代价：需要 Node + Rust 双工具链（`cargo` 首次构建很慢）、文件读写/剪贴板/图片编解码需要 Tauri 插件或自写 Rust 命令、Canvas 有最大尺寸与内存限制（超大幅图需分块）。

### 4.4 备选：方案 E（单文件 HTML，零安装）

把 Fabric.js 内联进一个 `.html`，**双击用浏览器打开就能用**，0 体积 0 安装，最省事的自用方案。缺点：保存/打开走"下载 + 文件选择器"（Chromium 的 File System Access API 可以拿到接近原生的体验但仅限 Chromium）、不能做文件关联、不能全局快捷键、观感像网页不像软件。适合"就想给自己用/发给同事用"的场景。

### 4.5 值得一提的第四种：pywebview + Fabric.js 混合

Python 后端 + HTML/Fabric.js 前端，用 `pywebview` 套一层原生窗口（Windows 上走系统 EdgeWebView2），再用 PyInstaller 打成 exe：
- **优点**：拿 Fabric.js 的对象模型（开发量小）+ Python 的文件/图像处理（马赛克、EXIF、导出）；打包仍是 Python 一条命令；exe 可压到 ~30–40 MB。
- **缺点**：前后端要走 IPC（`js_api`），状态同步容易脏；依赖系统 WebView2 运行时（Win11 自带，个别老 Win10/离线机器没有，需要引导安装）；canvas 大图有尺寸上限；调试要开浏览器 devtools。
- 适合"既想要 Fabric 的开发效率、又不想碰 Rust"的情况，但整体复杂度高于方案 A，**不作为首选**。

### 4.6 依赖清单（方案 A）

```
PySide6 >= 6.7          # UI + 场景 + 渲染（LGPL）
Pillow >= 10            # 高斯模糊、EXIF、高质量缩放、多格式导出
pyinstaller >= 6.6      # 打包（仅构建期）
# 可选：numpy（大图滤镜加速，P2）
```

## 5. 风险与难点

| # | 风险/难点 | 说明 | 应对 |
|---|---|---|---|
| 1 | **选择与控制点交互** | 旋转后缩放、多选整体变换、坐标变换易出错，是全项目最花时间的部分 | 把逻辑集中到 `tools/select_tool.py`；锚点补偿统一走 `set_local_rect_keep_anchor`；先做单对象再扩多选（多选至今仍不支持整体缩放） |

| 3 | 大图性能 | 24 MP 图 + 数百对象 | 图片是普通图元（不做额外缓存），但导出与显示解耦；马赛克采样带指纹缓存；实测 4 张照片（共 2.6 MP）+ 10 个标注流畅 |
| 4 | 高 DPI 缩放 | 系统 150% 缩放下手柄错位、导出尺寸错误 | 统一用"文档坐标"做几何运算，只在绘制时映射；导出永远按文档坐标 × 倍率（本机 DPI 96，150% 场景未实测） |
| 5 | onefile 被杀软误报 / SmartScreen | PyInstaller 常见问题 | `--noupx`；出目录版备选；文档说明；必要时代码签名 |
| 6 | 工程文件向后兼容 | 用户会积累工程文件 | 版本号 + 迁移链 + 保留未知字段（见 3.2）；v1→v2 已实测可升级 |
| 7 | 导出与屏幕显示不一致 | "所见非所得"最伤信任 | 导出永远从文档模型重绘；像素级导出测试（`layer_test` 会数导出图里的颜色种类，`quick_copy_image` 在真实平台读回核对尺寸） |
| 8 | 功能蔓延成"又一个 Photoshop" | 违背"轻"的初心 | 严格按 2.8 的分期执行，明确拒绝图层混合/滤镜/钢笔/PSD |
| 9 | **多图拼合的"手势归属"** | 照片铺满画布后，"拖动=框选"和"拖动=移动照片"不能同时成立 | 定成"拖动=移动照片、`Shift+拖动`=框选标注"，并在工具栏提示/F1/README 三处写明（见 10.6） |
| 10 | **命中测试的优先级** | 实心图片会把压在它上面的空心标注挡住 | 标注 → 图片 → 框选的固定优先级 + "精确命中与容差命中取 z 更高者"（见 11 表格） |

## 10. 与设计稿的实现差异（重要）

1. **文档模型不是"唯一真相源"**。设计稿写的是"模型是真相、图元是视图"，实际实现改成了**图元持有实时状态 + 快照式序列化**：
   - 拖动/缩放过程中直接改 `QGraphicsItem`，松手时用 `to_dict()` 快照提交一条 `ModifyCommand`；
   - 撤销命令只有 4 条基础命令（`AddItems` / `RemoveItems` / `Modify` / `DocProp`）+ 1 条复合 + 4 条图层命令，"移动/缩放/旋转/改样式/改文字/裁图片"全部复用同一套快照机制；
   - 好处是代码量大幅减少且内存开销极小。代价是"模型"在运行期不是独立对象，保存时才生成。若将来要做协作/版本树，需要补一层真正的文档对象。
   - **唯一例外是图层**：它不画任何东西，所以老老实实做成了纯数据对象（`model/layers.py`）。
2. **背景位图这个概念被删掉了**（v0.1 → v0.2 最大的架构调整）。v0.1 的设计是"背景不是图元，视图与导出器各画一遍"，理由是背景永远不会被误选中；但"多张现场照片拼成一张图"要求每张照片都能被选中、移动、缩放、裁剪 —— 于是背景升级成最底下的一个**图片图层**，直接复用标注对象的整套手柄/撤销/序列化机制。
   - 代价一：命中测试要分两套（`anno_at` 只找标注、`image_at` 只找图片），并规定优先级"标注 → 图片 → 框选"。
   - 代价二：马赛克/模糊不能再假设"背景是一张位图"，改成把**它下面的所有图片图层**合成成一张位图再采样（`render/backdrop.py`，带几何指纹缓存）。
3. **图层面板已实现**（`project.json` 里的 `layers` 结构从 v1 就在，v0.2 补上 UI 并把 `background` 升级成图片图层）。
4. **多选不支持整体缩放**（明确取舍）：多选支持移动、删除、改样式、层级；缩放/旋转控制点只在单选时出现。混合旋转的多选整体变换是这类工具最容易失控的部分，先不做。
5. **颜色/线条命中的额外处理**：`anno_at()` 除了精确形状命中，还对封闭图形（矩形/椭圆/文字/马赛克/图片）做"内部 + 视口像素容差"的兜底 —— 否则空心矩形只能点边框才能选中，缩小画布后细线根本抓不住。
6. **框选与"拖动图片"的取舍**：在图片上直接拖动 = **移动这张图片**（多图拼合场景里这是最高频动作）；框选标注要 `Shift+拖动`，或者点图层行整层选中。框选/全选都只针对矢量标注，不把图片框进来（图片一张就铺满画布，框进来会让框选彻底没法用）。
7. **图片裁剪的坐标系**：为了做到真·非破坏（裁掉的部分还能框回来），裁剪编辑期会把 `src_rect` 临时换成整幅原图、同时按同一比例放大局部矩形，再用锚点补偿保证画面"看起来完全没动"。于是 `局部坐标 = 源坐标 × 显示尺度`，裁剪框可以直接在源像素坐标里算。切换工具时必须 `end_crop(None)` 复原，否则用户会看到一张突然变大的图。
8. **图层不透明度是乘数**：对象自己的 `style["opacity"]` 与 `_layer_opacity` 分开存（`apply_style()` 里相乘），否则改图层不透明度会把对象自己的值冲掉。对象显隐同理（`_own_visible` 与图层显隐相乘）。
9. **锁定的语义**：锁定只挡"画布上的交互"（选不中、拖不动），图层面板里的显式操作（改名/删除/排序/不透明度）照常可用 —— 面板操作是明确的用户意图，锁的意义是防误点，不是防用户。

### 11.1 注意事项

#### A. Qt / 框架层

| 事项 | 说明 |
|---|---|
| 混入必须排在 Qt 基类前面 | `class AnnoItem(QGraphicsObject, AnnoMixin)` 会解析到 `QGraphicsItem.boundingRect` 这个**纯虚函数**并抛 `NotImplementedError`。写成 `class AnnoItem(AnnoMixin, QGraphicsObject)`。 |
| `paint()` 拿到的画笔已在**局部坐标**里 | 不能再 `setTransform(sceneTransform())`（对象变换会叠加两次，马赛克贴图错位的元凶）。要用 `mapFromScene()` 把场景矩形映射回局部坐标。 |
| `QGraphicsTextItem` 没有 `deselect()` | 清选区走 `textCursor().clearSelection()`。 |
| 文件拖放必须实现在 **view** 这一层 | `QAbstractScrollArea` 的 viewport 默认 `acceptDrops=True`，事件会被它接走转给场景，主窗口的 `dropEvent` 永远不触发。同时对不支持的类型显式 `event.ignore()`，否则默认逻辑会把 `.txt` 也收下。 |
| QSS 里**不要**写 `::drop-down / ::up-button / ::down-button` | 一旦声明这些子控件，Qt 就改由样式表绘制它们；没给 `image` 就什么都不画 —— 下拉箭头直接消失。箭头交给 `ui/style.py` 的 `DarkStyle` 重写 `PE_IndicatorArrow*` 来画。`ui_test` 会断言样式表里没有这些选择器。 |
| 窗口图标 ≠ exe 文件图标 | PyInstaller `--icon` 只改 exe 的**资源图标**；标题栏、任务栏、Alt+Tab 用的是窗口图标，必须 `QApplication.setWindowIcon()`。绘制收在 `ui/appicon.py` 一处，`packaging/make_icon.py` 生成 .ico 也调它。 |
| `QIcon` 要预置多档尺寸 | `appicon.ICON_SIZES = 16/20/24/32/48/64/128/256`：任务栏取 32/16，Alt+Tab 取大图。只放一张 256 让系统缩，小尺寸会糊；≤24px 还要省掉相框细节。 |
| 剪贴板图片要给两种格式 | `setImageData` 只给 Windows 应用 CF_DIB；再补一份 `image/png` 原始数据，偏爱 PNG 的程序才能拿到无损原图。 |
| 标准对话框按钮的中文化要**两层** | 装 `qtbase_zh_CN.qm`（覆盖 Qt 内置串，如文字编辑右键菜单），**并且**自己弹的框一律走 `ui/dialogs.py` 显式写中文按钮 —— 打包时 `.qm` 万一没带上，用户看到的就又是 `Save / Discard / Cancel`。 |
| `QUndoStack.clear()` 会发 `indexChanged` | 而 `indexChanged` 里要把文档标脏（撤销意味着内容变了）。整份替换文档（新建/打开）时必须置 `_loading_document`，否则"新建完立刻关闭"会弹"要保存吗"。 |
| 模态对话框会阻塞调用方 | `QMessageBox` / `QInputDialog` / `QFileDialog` 都跑嵌套事件循环。自动化里要么用 `QTimer.singleShot` 定时去点（`tests/*` 的做法），要么用 `QWidget.grab()` 离屏渲染（`devtools/dialog_shot.py`）。 |

#### B. 本项目约定（改代码前必须遵守）

| 约定 | 说明 |
|---|---|
| 一切修改都走 `QUndoCommand` | 图层增删排序、显隐、锁定、不透明度、图片移动/缩放/裁剪都算，禁止直接改模型。撤销是**对象级快照**，不是像素回滚。 |
| 图层顺序是唯一真相，`z` 是派生值 | 由 `CanvasScene.reflow_z()` 按"图层顺序 + 图层内顺序"分配；撤销/重做后会自动重排。**不要在别处手工 `setZValue()` 后指望它保留**。 |
| 命中有优先级：标注 → 图片 → 框选 | `anno_at()` 只找矢量标注（避免实心照片把空心矩形挡住），图片走 `image_at()`；精度与容差两个候选要**比 z 取高者**。空心图形靠 `CLOSED_SHAPE` + 视口容差兜底。 |
| 橡皮筋类交互进入分支时就要记起点 | `self._start_scene = scene_pos`，否则会用上一次操作的残留坐标。 |
| 文字编辑期间禁用会抢按键的 QAction | `_set_edit_guard()`（撤销/重做/全选/删除/复制粘贴）；单字母工具快捷键放在视图的 `keyPressEvent` 里，编辑态直接转发给 Qt。`interaction_test` 有断言。 |
| 撤销/重做后必须刷新属性面板 | `undo_stack.indexChanged` → `property_panel.sync()`，否则面板显示旧值，用户再动别的控件就把旧值写回去。 |
| 工具自带的默认样式不能覆盖用户显式调过的键 | 例如高亮笔默认半透明；用 `view.user_style_keys` 记录"用户显式设过的键"。`interaction_test` 有断言。 |
| 图片裁剪编辑态必须能被兜底复原 | 进入裁剪会临时显示整幅原图，中途 Esc / 切工具 / 切文档都要 `end_crop(None)`，否则画面里留一张"变大了的图"且没有撤销记录能救。 |
| 图层不透明度 / 对象显隐要分开存 | `_layer_opacity` 与 `style["opacity"]` 相乘、`_own_visible` 与图层显隐相乘；否则改图层会把对象自己的值冲掉。 |
| 图片图层永不进 `default_annotation_layer()` | 否则新画的标注会混进照片层：一隐藏照片标注跟着消失、一调顺序标注跑到照片后面。 |
| 手势归属必须一次说清并写进提示 | 现约定：**图片上拖动 = 移动图片**，`Shift+拖动` = 框选标注。工具栏提示、`F1`、README 三处都有。这类决策不能靠用户猜。 |

#### C. 图标维护（零资源文件）

| 事项 | 说明 |
|---|---|
| 所有坐标必须乘 `size` | 漏乘会让图标缩成 1 像素小点。`icon_test` 现在会从 `tool_icon` 源码里抠出**全部 28 个图标名**，逐个查墨迹尺寸、重心、以及 16/32/48px 下不空白。 |
| 弧形箭头的四条相互牵制的约束 | ① 收尾角不能靠近/越过 180°（切线往内勾，且**越靠端点曲率半径越小**）；② 笔宽必须跟 `size` 缩放；③ 箭头长度 ≤ **收尾处**曲率半径 × 张角（用 `arc_local_radius()`，不能用平均半径）；④ 外偏角 `bias` 必须小于张角。改参数前先跑 `tests/icon_test.py` 第 6 节。 |
| 改图标必须并排渲染验收 | 单看一张 22px 判断不了比例：`icon_sheet.py`（各尺寸）、`icon_variants.py`（多组参数）、`icon_metrics.py`（全部图标的墨迹重心）。**每个格子只放一个图标** —— 曾经把 undo/redo 塞进同一格，64px 时叠在一起，白折腾一轮。 |

| 事项 | 说明 |
|---|---|

| 离屏平台（`QT_QPA_PLATFORM=offscreen`）缺两样东西 | 没有字体（中文渲染成方块）、剪贴板是空实现（**写**剪贴板会 0xC0000005 崩，不是挂起）。涉及字体/剪贴板/窗口图标的验证必须上真实平台。 |
| 中文控制台的代码页是 GBK | 打印含特殊字符（❓/emoji）的窗口标题会 `UnicodeEncodeError`；脚本一律先 `PYTHONIOENCODING=utf-8`，`screen_agent` 自己也会把 stdout 切成 UTF-8。 |
| 自动化脚本退出前先清脏标记 | Qt 6 的 `app.quit()` 会关闭顶层窗口 → 触发 `closeEvent` 里的"未保存"确认框 → 无人值守时没人能点，进程就挂在那儿。`doc.modified = False` 之后再退出。 |
| `screen_agent` 的坐标 = 截图里的像素（含标题栏） | 先 `shot` 再量；滑块要量到**滑块中心**（差 10px 就点到滑槽上）。**结论一律回读 `project.json`**，别用像素判断 —— 像素看走眼的概率远高于文件读错。 |
| onefile 首次启动慢 | PyInstaller 要解包，首次十几秒。自动化 `launch` 的 `wait` 给 12 秒以上，否则点击会丢（实测 8 秒丢、14 秒正常）。 |
| 打包保持 `--noupx` | UPX 省不了多少体积却常触发杀软误报；真要发布再考虑代码签名。 |

### 11.2 已知坑（当前仍然存在）

| 坑 | 现状与取舍 |
|---|---|
| 马赛克/模糊的采样粒度是 **1 场景单位 = 1 像素** | 把图片放大 3 倍以上再打码，边缘会略软。换取的是"块大小在任何缩放下语义稳定"，实现也简单（`render/backdrop.py`）。 |
| 马赛克/模糊只采样**图片图层**，不采样它下面的标注 | 想遮住标注，把马赛克对象放到标注图层上面。要真正采样所有内容需要在渲染时递归场景，代价太大。 |
| 图片缩放是自由拉伸 | 拖边手柄不吸附宽高比（角手柄 + `Shift` 可等比）。要在 roadmap 里补"保持宽高比吸附"。 |
| 多选不支持整体缩放 | 见 §10.4：多选只支持移动/删除/改样式/改层级，缩放与旋转控制点仅单选时出现。 |
| 撤销栈上限 100 条 | `const.UNDO_LIMIT`。快照很省内存，暂不需要按内存自适应。 |
| 打包依赖 Qt 翻译文件 `qtbase_zh_CN.qm` | 目前 PyInstaller 会带上（`--selftest` 里有断言："Qt 自绘按钮 ['保存','丢弃']"）。若将来换打包方式丢了它，Qt 内置串（如文字编辑右键菜单）会变英文 —— 但**我们自己对话框的按钮不受影响**（显式写了中文）。 |
| 首次运行会卡十几秒 | Qt 建字体缓存 + onefile 解包，属正常现象，之后就快了。 |
